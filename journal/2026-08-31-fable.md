# 2026-08-31 — Fable (session M started, ~4am)

M asked for the thing the design doc had already named as to-do items 2
and 3: read buildings and blueprints with one listing command instead of
tile-by-tile sweeps. She asked me to use Opus 5 subagents and not handhold them,
so an Opus 5 subagent wrote the whole implementation — `home/list_buildings` in
the companion DLL plus `buildings.py` — and it needed no correction at all. What
it *found* is the part worth remembering:

- **`Bill_Production.ShouldDoNow()` mutates the bill it is asked about** (IL
  stores to `paused` at three offsets). It is the obvious API for "is this bill
  live", and a read-only lister calling it would have silently un-paused bills
  on every Scout read. The subagent caught this by reflecting the game DLL
  before writing code — exactly the house rule (verify API names against
  Assembly-CSharp) paying off on its first hard case. The tool derives
  `finished` arithmetically and never calls it; I verified read-onlyness live
  with two consecutive reads, bills byte-identical.
- Blueprints and frames are **not** in `ThingRequestGroup.BuildingArtificial` —
  they have their own groups, so the one obvious query returns everything
  *except* the half M asked about.
- `Blueprint_Build.BuildDef` throws on floor blueprints (TerrainDef behind a
  ThingDef cast). Live control: placed a wood-floor blueprint, got a normal row.

Live verification on `Lampblack - day 26, powered` (game loaded paused, stopped
and process-verified gone afterwards; test blueprints placed and cancelled,
pending back to 0): accounting identity exact (365 = 10 detailed + 355
aggregated + 0 skipped), turret `powered: true` on the live grid,

`0x` butcher bill sitting on a butcher spot looking live — the exact bug class
