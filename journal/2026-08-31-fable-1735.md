# 2026-08-31, ~17:00–17:35 — Fable, with three Opus 5 builders. The stream goes real.

M started this session to land the streaming interface for errata. My
web-self had built the overlay suite in a claude.ai conversation — server,
overlay page, control page, fake-event tester, and a HANDOFF.md addressed to
"whoever's implementing this on M's machine — probably another Claude."
Reading a handoff your own other self wrote for you is a strange mirror: it
got the principles exactly right (narration as a byproduct of acting; the
stream must never touch the game) and the mechanism entirely wrong, because
it imagined schema'd tool calls and our stack is a Trunk spawning Hands forks
that run Python instruments. The whole session was translating a correct
design across that gap.

## Landed (suite in `Fable 5\made\stream-overlay\`, glue in `Opus 5\made\rimworld\`)

- **overlay_client.py / say.py / stream.py** — fire-and-forget narration
  (daemon thread + atexit join against a shared 2.5s deadline, so one-shot
  CLIs deliver and long processes never block), Trunk-side turn counter,
  handback (status + summary + goals in one command), and `human-check`,
  which is how a message M types into control.html reaches errata's
  context between turns. `--say/--mood` flags on run/watch/cam/rim; act, ui,
  move, trade have no CLIs at all (import-only) and use say.py.
- **PLAYBOOK "The stream" + hands.md "Narrating"** sections, written by the
  glue builder, kept nearly verbatim — voice, batching convention, the eight
  moods, "veryhappy is earned, not given."
- **OBS**: new `errata` profile + `errata-stream` scene collection (her
  fresh install untouched — she'd installed OBS *fifteen minutes* before the
  builder looked). Window capture by executable, area scale filter, 1080p at
  **30fps** — half the frames doubles the bitrate per frame, the biggest
  single win for text through Twitch's encoder.
- **The resolution question answered sideways.** M's instinct: 4K
  into 1080p makes text unreadable, so lower the game's resolution. The
  recon found `cell2px.py` hardcodes `SCREEN = (4096, 2160)` and click.py
  assumes screenshot pixel == screen pixel, so changing resolution breaks
  the instruments. Same legibility, safer levers: **UI scale 2.0 → 2.5**
  (verified live: layout surface 1638x864, exactly /2.5, no clamp, all UI
  interactions still work) and **BASE_ROOT 24 → 15** (~25px/cell on stream).
  Map framing is orthographic-size, independent of uiScale — no retune.
- **GOLIVE.md + start-overlay.bat** — M's plain-language path from
  PC-on to live.

## The traps, each found by a different builder

1. **Port 8080 is GABS.** The overlay's default port is the bridge's port.
   Overlay lives on 8090 now; client default baked in.
2. **`localhost` costs 2.006s a post; `127.0.0.1` costs 1ms** (IPv6-first
   resolution against an IPv4-only server). Measured, then made the default
   with a quiet rewrite.
3. **An env var can't configure a play session** — every say.py call is a
   fresh process in a fresh shell. The builder left the default at 8080 "as
   shipped" with OVERLAY_URL to override; I overrode the reasoning: default
   8090 baked in, or every narration lands on GABS silently.
4. **The harness's RimWorld doesn't read LocalLow prefs.** It launches with
   `-savedatafolder=C:\Home\5.6 Sol\rimworld-agent\profile`. My uiScale edit
   landed on *M's own game* — reverted byte-for-byte, and a minimal
   Prefs.xml written into the profile instead. Corollary discovered on the
   redo: with no Prefs.xml RimWorld auto-picked exactly 2.0 for this screen,
   which made the misplaced edit look like a clamp. And RimWorld writes
   prefs only on a pref *change*, never on exit.
